CREATE INDEX  - а где хранятся созданные индексы ? в таблице где находятся сами значения или сощдаётся новая ?


Отличный вопрос! Индексы хранятся **ОТДЕЛЬНО** от таблицы.

## Где хранятся индексы?

**Индекс** = отдельная структура данных на диске (отдельный файл в файловой системе PostgreSQL)

```
На диске PostgreSQL:
├── Файл таблицы menu
│   └── Содержит: все строки с данными (id, pizzeria_id, pizza_name, price)
│
└── Файл индекса idx_menu_pizzeria_id
    └── Содержит: 
        - Отсортированные значения pizzeria_id
        - Указатели (ссылки) на строки в таблице menu
```

## Аналогия из C

Если знаешь указатели в C, то:

```c
// Таблица = массив структур
struct menu {
    int id;
    int pizzeria_id;
    char pizza_name[100];
    float price;
};

struct menu table[1000]; // Сама таблица

// Индекс = отдельный массив указателей, отсортированный по pizzeria_id
struct index_entry {
    int pizzeria_id;           // Копия значения для быстрого поиска
    struct menu *pointer;      // Указатель на строку в таблице
};

struct index_entry index[1000]; // Отдельная структура (индекс)
```

## Что содержит индекс?

**Индекс idx_menu_pizzeria_id** содержит:
1. **Копию** значений столбца `pizzeria_id` (отсортированную)
2. **Ссылки** (указатели) на физическое расположение строк в таблице `menu`

```
Таблица menu (неупорядоченная):
строка 1: id=10, pizzeria_id=3, pizza_name="Margherita", price=10.5
строка 2: id=11, pizzeria_id=1, pizza_name="Pepperoni", price=12.0
строка 3: id=12, pizzeria_id=2, pizza_name="Cheese", price=8.0

Индекс idx_menu_pizzeria_id (отсортирован):
pizzeria_id=1 → указатель на строку 2
pizzeria_id=2 → указатель на строку 3
pizzeria_id=3 → указатель на строку 1
```

## Где хранится информация ОБ индексах?

**Метаданные** (информация об индексах) хранятся в системной таблице `pg_indexes`:

```sql
SELECT * FROM pg_indexes WHERE tablename = 'menu';
```

Вернёт:
```
schemaname | tablename | indexname              | tablespace | indexdef
-----------+-----------+------------------------+------------+----------
public     | menu      | idx_menu_pizzeria_id   | NULL       | CREATE INDEX...
```

Но это только **описание** индекса, а не сами данные индекса!

## Почему индексы отдельно?

**Преимущества:**
- ✅ Можно создавать/удалять индексы без изменения таблицы
- ✅ Один столбец может иметь несколько индексов разных типов
- ✅ Индексы можно перестраивать (REINDEX) отдельно

**Недостатки:**
- ❌ Занимают дополнительное место на диске
- ❌ При INSERT/UPDATE/DELETE нужно обновлять и таблицу, и все её индексы (медленнее)

## Сколько места занимает индекс?

Можно проверить:

```sql
-- Размер таблицы menu
SELECT pg_size_pretty(pg_total_relation_size('menu')) AS table_size;

-- Размер индекса idx_menu_pizzeria_id
SELECT pg_size_pretty(pg_relation_size('idx_menu_pizzeria_id')) AS index_size;
```

Обычно индекс занимает **20-50%** от размера таблицы (зависит от количества и размера индексированных столбцов).

---

**Итого:** Индекс = отдельный файл с копией данных + ссылками на строки таблицы. Поэтому индексы ускоряют SELECT, но замедляют INSERT/UPDATE/DELETE.
